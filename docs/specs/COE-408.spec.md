# COE-408 — Triage Queue API Endpoint

**Jira:** COE-408  
**Endpoint:** `GET /api/referrals/triage-queue`  
**Auth:** Required (JWT)

---

## Overview

Returns all referrals with `status = received`, sorted by clinical urgency and age, with a server-computed `slaBreached` field on each record. No client-side sorting or SLA logic is needed.

---

## Authentication

Identical to all other protected endpoints. Token resolved in this order:

1. `token` HttpOnly cookie
2. `Authorization: Bearer <token>` header

Missing or invalid token → `401 UNAUTHORIZED`.

---

## Query Parameters

| Parameter | Type    | Default | Max  | Description                        |
|-----------|---------|---------|------|------------------------------------|
| `limit`   | integer | `20`    | `100`| Max records per page               |
| `offset`  | integer | `0`     | —    | Zero-based record offset           |

Non-numeric values for either param fall back to their defaults. `limit` values above 100 are clamped to 100.

No other query parameters are accepted. The `status` filter is hardcoded server-side to `received`; passing `status` as a query param has no effect.

## Sort Order

Results are sorted by two keys, applied in this order:

1. **Priority** — emergent first, then urgent, then routine:
   ```sql
   CASE priority WHEN 'emergent' THEN 1 WHEN 'urgent' THEN 2 ELSE 3 END ASC
   ```

2. **Age within tier** — oldest `receivedAt` first:
   ```sql
   received_at ASC
   ```

Full `ORDER BY` clause:
```sql
ORDER BY
  CASE priority WHEN 'emergent' THEN 1 WHEN 'urgent' THEN 2 ELSE 3 END ASC,
  received_at ASC
```

---

## `slaBreached` Field

Computed server-side in SQL. A referral is breached when all three conditions hold:

- `status = 'received'`
- `priority IN ('urgent', 'emergent')`
- `NOW() - received_at > INTERVAL '24 hours'`

SQL expression (from `ARCH.md → SLA Calculation`):

```sql
(
  priority IN ('urgent', 'emergent')
  AND EXTRACT(EPOCH FROM (NOW() - received_at)) / 3600 > 24
) AS "slaBreached"
```

All timestamps are stored and compared in UTC. For `routine` referrals, `slaBreached` is always `false`. For referrals where `received_at IS NULL`, `slaBreached` is `false`.

## SQL Shape

The query extends the shared `REFERRAL_SELECT` fragment (defined in `api/src/routes/referrals.ts`) with the `slaBreached` expression and a fixed `WHERE` clause:

```sql
SELECT
  r.id,
  r.specialty_requested         AS "specialtyRequested",
  r.reason,
  r.priority,
  r.status,
  r.authorized,
  r.clinical_notes              AS "clinicalNotes",
  r.received_at                 AS "receivedAt",
  r.triaged_at                  AS "triagedAt",
  r.scheduled_at                AS "scheduledAt",
  r.completed_at                AS "completedAt",
  r.created_by                  AS "createdBy",
  r.created_at                  AS "createdAt",
  r.updated_at                  AS "updatedAt",
  (
    priority IN ('urgent', 'emergent')
    AND EXTRACT(EPOCH FROM (NOW() - received_at)) / 3600 > 24
  )                             AS "slaBreached",
  json_build_object(
    'id',          p.id,
    'firstName',   p.first_name,
    'lastName',    p.last_name,
    'dateOfBirth', p.date_of_birth,
    'patientId',   p.patient_id
  )                             AS patient,
  json_build_object(
    'id',         rp.id,
    'name',       rp.name,
    'specialty',  rp.specialty,
    'providerId', rp.provider_id
  )                             AS "referringProvider",
  CASE WHEN r.receiving_provider_id IS NOT NULL THEN
    json_build_object(
      'id',         ep.id,
      'name',       ep.name,
      'specialty',  ep.specialty,
      'providerId', ep.provider_id
    )
  ELSE NULL END                 AS "receivingProvider"
FROM referrals r
JOIN patients  p   ON p.id  = r.patient_id
JOIN providers rp  ON rp.id = r.referring_provider_id
LEFT JOIN providers ep ON ep.id = r.receiving_provider_id
WHERE r.status = 'received'
ORDER BY
  CASE priority WHEN 'emergent' THEN 1 WHEN 'urgent' THEN 2 ELSE 3 END ASC,
  received_at ASC
LIMIT $1 OFFSET $2
```

## Error Responses

All errors use the project-standard envelope:

```json

```

| Status | Code            | Condition                              |
|--------|-----------------|----------------------------------------|
| `401`  | `UNAUTHORIZED`  | No token, or token invalid/expired     |
| `429`  | `RATE_LIMITED`  | Rate limit exceeded                    |
